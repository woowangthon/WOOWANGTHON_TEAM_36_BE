# '확인 필요' 판정 기준 수정 설계 (추출 프롬프트 v6)

- 작성일: 2026-11-12
- 상태: 승인 (2026-11-12)
- 브랜치: `feat/extract-v6-condition-classes` (`main` 3f9cbba에서 분기)
- 분류표: 작업 공간 `docs/조건문장_분류표.md` (이 문서 3장과 같은 내용)

## 1. 목적

v5(#48)는 필드로 옮기지 못한 조건 문장을 세 목록으로 나눴습니다. `extra_conditions`는 확인 필요가 되고, `basic_conditions`와 `notes`는 판정에 영향을 주지 않습니다. 그런데 v5 골든셋 결과를 보면 확인 필요가 되지 않아야 할 문장이 아직 `extra_conditions`에 들어갑니다.

- **Case 1**: 프로필로 계산할 수 있는 조건입니다. 예: "신·편입생 제외", "잔여정규학기 1개 학기 이상", "2학년 1학기 진학 예정자", "지방 소재 대학교 재학생".
- **Case 2**: 조건이 아닌 안내입니다. 예: "예산 소진 시까지 지원", "학적변동 시 추가지원금 환수", "수여식 불참 시 선발 취소".

이 두 경우 때문에만 확인 필요가 되는 장학금을 없애고, 나머지 자격 조건(Case 3)은 지금처럼 확인 필요로 두는 것이 목표입니다.

## 2. 결정 사항

| 항목 | 결정 |

| 애매한 문장 | v5와 같이 `extra_conditions`에 넣습니다 |

## 4. 변경 내용

### 4.1 추출 스키마 (`app/extraction/schemas.py`, 공용)

`ScholarshipCriteria`에 아래 필드를 추가하고 `CriteriaField`에도 넣습니다. 기본값이 `None`이라 DB에 저장된 v5 결과도 그대로 읽힙니다. 장학금 조건은 `scholarships.criteria`(JSONB)에 통째로 저장되므로 Alembic 마이그레이션은 필요 없습니다.

| 필드 | 형식 | 의미 |
| --- | --- | --- |
| `excludes_new_students` | `bool \| None` | 신입생·편입생 제외면 `true`. 조건이 없으면 `null`(`false`도 쓰지 않음) |
| `min_remaining_semesters` | `int \| None` (1~8) | 남은 정규학기가 N학기 이상이어야 함 |

### 4.2 규칙 엔진 (`app/matching/rules.py`, `engine.py`)

| 조건 | 규칙 |
| --- | --- |
| `excludes_new_students` | `true`가 아니면 비교하지 않음. 이수학기 0이면 불충족, 1 이상이면 충족 |
| `min_remaining_semesters` | `null`이면 비교하지 않음. `8 − 이수학기 ≥ N`이면 충족, 아니면 불충족. 이수학기는 마친 학기 수라서 지금 다니는 학기도 남은 학기로 셉니다 |

- 이수학기는 필수 값이라 프로필 때문에 알 수 없음이 되는 경우는 없습니다. 필드가 `ambiguous_fields`에 있으면 다른 조건처럼 알 수 없음입니다.
- `RULES`에서는 `excludes_extra_semester` 바로 뒤에 둡니다. 체크리스트 순서도 같습니다.
- `app/schemas/api/scholarships.py`의 `ConditionName`에 두 이름을 추가합니다(API 계약 변경, 6장).

### 4.3 프롬프트 v6 (`app/extraction/prompts/extract_v6.md`)

v5를 복사한 뒤 아래를 바꿉니다. `extractor.PROMPT_VERSION`을 `extract_v6`로 올립니다.

- 규칙 7(세 목록)을 3.1 분류표와 경계 원칙대로 고칩니다. 목록마다 예시를 늘립니다.
- v5에서 옮길 예시: `basic_conditions`의 "중복 수혜(참여) 제한, 수혜 횟수 제한, 기존 장학생 제외"와 `notes`의 "관리지침·규정을 따른다는 문장"을 `extra_conditions`로 옮깁니다. `basic_conditions`는 학교 정보로 알 수 있는 조건과 징계·품행 조건만 남깁니다.
- 서비스 대상 학교(충북대학교: 국립 4년제, 청주 소재 지방 대학, 소프트웨어학부는 4년제 학과)를 적고, 학교 정보로 충족 여부를 알 수 있는 조건은 `basic_conditions`에 넣게 합니다.
- 필드별 규칙에 새 필드 2개를 추가합니다. "진학 예정 학년·학기"는 `target_grades`로 옮긴다는 기존 규칙을 다시 강조합니다.
- v5의 `extra_conditions` 예시 중 "신·편입생 제외"와 "잔여 정규학기 수"를 빼고 새 필드 규칙으로 옮깁니다.

### 4.4 골든셋 (`tests/fixtures/golden/`, `eval/`)

- 정답 JSON을 새 기준으로 고칩니다. 세 목록의 분류를 바꾸고 새 필드 값을 넣습니다. 고친 정답은 사람이 검토합니다.
- 채점(`eval/scoring.py`): 새 필드 2개를 보조 지표(`AUX_FIELDS`)로 셉니다. 전체 정답률(`correct`·`total`)에는 넣지 않아 v5 결과와 그대로 비교할 수 있습니다. `needs_check`는 그대로 둡니다.
- `uv run python -m eval.run`을 실제로 실행하고 `eval/results/gemini-3.8-flash+extract_v6.json`을 커밋합니다.

### 4.5 문서

- 계획서 5.2 표: 새 필드 2개와 세 목록(`extra_conditions`·`basic_conditions`·`notes`)을 반영합니다. v3~v5에서 추가했는데 표에 빠진 필드(`min_score_100`, `grade_basis`, `evidence_source`)도 함께 맞춥니다.
- 계획서 5.3: 판정 2단계 설명과 조건별 비교 표에 새 조건 2개를 추가합니다.
- `tests/fixtures/golden/README.md`: 분류 기준이 v6로 바뀌었다고 적습니다.

| `rules.min_remaining_semesters` | 조건 없음 → 비교 안 함, 경계값(N=1에서 이수학기 7 충족·8 불충족, N=2에서 6 충족·7 불충족) |
| `engine.evaluate` | 새 조건이 체크리스트에 들어감, ambiguous면 알 수 없음, 새 조건 불충족이면 지원 불가 |
| 스키마 | 새 필드 범위 검사(`min_remaining_semesters` 0·9 거부), v5 저장 결과(필드 없음) 읽기 |
| 추출기 | `model_version`이 `+extract_v6`로 끝남, 프롬프트 파일이 로드됨 |
| 채점 | 새 보조 지표가 전체 정답률에 들어가지 않음 |

테스트는 Gemini를 호출하지 않습니다. 실제 호출은 `eval.run`에서만 합니다.

## 6. 영향 범위

- **frontend**: `ConditionName`에 값 2개가 늘어납니다. `npm run gen:api`로 타입을 다시 만들고, 체크리스트 라벨 2개("신·편입생 제외", "남은 정규학기")를 추가하는 PR이 따로 필요합니다. 두 PR은 서로 링크합니다.
- **기존 데이터**: 저장된 v5 결과는 새 필드가 없어 판정이 바뀌지 않습니다. 반영하려면 관리자 재추출로 `PENDING`을 기록하고, 다음 수집이 한 번에 20건씩 다시 추출합니다.
- **알림**: 대상 선정이 같은 규칙 엔진을 쓰므로, 재추출 뒤에는 알림의 지원 가능·확인 필요 구분도 함께 바뀝니다.

## 7. 위험

| 위험 | 대응 |
| --- | --- |
| 편입생 사용자를 "충족"으로 잘못 판정 | 편입생이 아니라고 간주한다는 것을 계획서 4.1·5.3에 적습니다. 프로필에 편입 여부 칸을 만드는 것은 범위 밖입니다 |

| 남은 정규학기 기준 시점 해석 차이 | "지금 다니는 학기도 남은 학기"로 정하고 규칙 docstring과 계획서에 적습니다 |
