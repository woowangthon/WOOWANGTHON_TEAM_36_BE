# 관심과 신청완료를 따로 표시하기 (T70 backend · T71 frontend)

2026-11-14

## 왜 바꾸나

지금은 사용자·장학금마다 상태가 한 값(`BOOKMARKED` 또는 `APPLIED`)입니다. 신청완료를 누르면 관심이 덮어써지고, 화면은 신청완료한 장학금의 하트를 숨깁니다. 신청한 뒤에도 관심 장학금으로 계속 모아 두고 싶은 사용자가 그렇게 할 수 없습니다.

## 목표

- 관심과 신청완료를 서로 영향을 주지 않는 두 표시로 저장합니다.
- 신청완료한 장학금에서도 하트를 켜고 끌 수 있습니다.
- 내 정보의 관심 탭과 신청완료 탭은 각자의 표시만 봅니다. 둘 다 켠 장학금은 두 탭에 모두 나옵니다.

## 하지 않는 것

- 숨기기(`HIDDEN`)를 되살리지 않습니다.
- 신청완료 배지, 상세 화면의 신청 완료 버튼 모양은 그대로 둡니다.
- 예전에 신청완료로 덮어써진 관심 표시는 복구하지 않습니다(기록이 없음).
- 구버전 화면을 위한 `my_state` 병행 응답은 두지 않습니다.

## 검토한 방법

1. **한 행에 불리언 두 칸** (선택): `bookmarked`, `applied`. 상태가 두 개로 고정이고, 목록 쿼리의 조인 한 번이 그대로 유지됩니다.
2. 상태마다 행 하나(기본키에 `state` 추가): 상태가 늘어날 때 유리하지만, 목록 쿼리가 조인 두 번이나 집계로 바뀝니다. 상태를 늘릴 계획이 없습니다.
3. 값 하나에 `BOTH` 추가: 저장은 그대로지만 `== "BOOKMARKED"` 같은 비교가 곳곳에서 조용히 틀립니다.

## 설계

### DB (`user_scholarship_states`)

- `state` 칸을 지우고 `bookmarked boolean not null default false`, `applied boolean not null default false`를 둡니다.
- 둘 다 `false`인 행은 지우지 않고 그대로 둡니다. 표시하지 않은 것과 똑같이 다룹니다. 행을 지우려면 "읽고 → 지울지 판단"이 필요해 동시에 누른 두 요청이 어긋날 수 있고, 그대로 두면 `PUT`이 문장 하나(upsert)로 끝납니다(계획 작성 중 변경, 2026-11-14).
- 마이그레이션: `BOOKMARKED` → `bookmarked = true`, `APPLIED` → `applied = true`. 되돌릴 때는 `applied`면 `APPLIED`, `bookmarked`만이면 `BOOKMARKED`, 둘 다 `false`인 행은 지웁니다.

### API

| 항목 | 지금 | 바꾼 뒤 |
| --- | --- | --- |
| 목록·상세 응답 | `my_state: "BOOKMARKED" \| "APPLIED" \| null` | `bookmarked: bool`, `applied: bool` |
| `PUT /scholarships/{id}/state` 요청 | `{state}` (통째로 바꿈) | `{bookmarked?: bool, applied?: bool}`. 보낸 값만 바꾸고 나머지는 그대로. 둘 다 없으면 422 |
| `PUT` 응답 | `{scholarship_id, state}` | `{scholarship_id, bookmarked, applied}` |
| `DELETE /scholarships/{id}/state` | 상태 지움 | 없앰(`PUT`에 `false`를 보내면 됨) |
| `GET /scholarships?state=bookmarked\|applied` | 그 상태인 것 | 그 표시가 켜진 것. 둘 다 켠 장학금은 양쪽에 나옴 |

- `PUT`은 보낸 칸만 `UPDATE`하므로 하트와 신청완료를 거의 동시에 눌러도 서로 덮어쓰지 않습니다.
- 같은 장학금 묶기(T45)의 대표 고르기는 "둘 중 하나라도 켠 것 먼저"로 뜻이 같습니다.

### 알림 메일 (7.4)

- 새 장학금: 신청완료한 것은 제외(지금과 같음).
- 마감 임박: 관심이고 **신청완료가 아닌** 장학금만. 관심과 신청완료를 둘 다 켠 장학금에는 보내지 않습니다(사용자 결정, 2026-11-14).

### 화면 (frontend, T71)

- `npm run gen:api`로 타입을 다시 만듭니다.
- 카드·내 정보 줄: 하트를 항상 보여 주고 `bookmarked`만 바꿉니다. 신청완료 배지와 "지원 불가 카드 흐리게" 예외는 `applied` 기준.
- 상세: 신청 완료 버튼은 `applied`만 바꿉니다.
- 내 정보 탭: 탭의 표시를 끄면 그 탭에서만 사라집니다. 예: 신청완료 탭에서 하트를 꺼도 그 줄은 남습니다.
- 저장 훅은 바꿀 칸만 보내고, 진행 중인 변경도 칸별로 화면에 먼저 반영합니다(9.8).
- MSW 목 데이터는 새 타입으로 옮기기만 합니다(관심 1건, 신청완료 1건 그대로). 둘 다 켠 경우는 테스트가 화면을 눌러 직접 만듭니다. 목 데이터에 미리 넣으면 "마지막 관심을 해제하면 빈 화면" 같은 기존 테스트의 전제가 바뀝니다(계획 작성 중 변경, 2026-11-14).
- 관심 탭의 빈 화면 문구가 "상세 화면에서 ‘관심’을 누르면"으로 남아 있어 "카드의 하트를 누르면"으로 고칩니다(하트는 T54에서 카드로 옮김).

### 문서

- 계획서 6장(표의 `state` 칸), 7.1(내 장학금), 7.2(상태 API), 7.4(마감 임박 조건)를 고칩니다.
- 작업카드에 T70(backend), T71(frontend)을 추가합니다. 번호는 코드 주석에 이미 쓰인 T54~T69와 겹치지 않게 골랐습니다.

## 배포 순서

API가 호환되지 않게 바뀝니다. backend를 먼저 머지·배포하고 바로 frontend를 머지합니다. 그 사이에는 구버전 화면에서 하트가 꺼진 것처럼 보이고 관심·신청완료 저장이 실패합니다(데이터는 안전).

## 구현자가 정할 것

- 마이그레이션 파일 이름과 revision id, 테스트 구성.
- 화면 저장 훅의 내부 타입 이름.
